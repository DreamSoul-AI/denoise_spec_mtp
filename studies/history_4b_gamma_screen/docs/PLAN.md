# PLAN — history_4b_gamma_screen

写在开跑之前。只在 first 26 上动 γ。β = 0.9999、λ = 0.1 沿用已经选定的值，不再搜索。

## 一、问题

已报告的均值加 gamma 只用了 γ = 1。在选参用的 first 26 上，γ = 1 的接受数是 777，更新均值（相当于这一支上的 γ = 0）是 704，冻结均值是 680。

γ 取 0.25、0.5、2、4 时，接受数是否高于已经记下的 777。

## 二、假设

这是筛选，不是确认。不预设哪一个 γ 更高。γ = 1 不重跑。

## 三、判定

1. 每一格 `exact_match_rate` 必须是 1，否则该格作废。
2. 主指标是 overall 的 `accept_d1`。
3. 若 0.25、0.5、2、4 全部小于或等于 777：停止。γ = 1 仍是测过的点里最高的。不开留出组。
4. 若有 γ 大于 777：取得最大的那个。并列时取更靠近 1 的值。只把这一个 γ 带到留出组。留出组是每类 skip 10、take 4，这 52 条没有参与过选参，也没有参与过 next 52 和 last 52。留出组上同时跑选出的 γ 和 γ = 1（γ = 1 在这组上没跑过）。留出组的假设是选出的 γ 高于 γ = 1。若不是，报告筛选切片上的高出没有复现。

## 四、固定

Qwen3-4B，float32，ModelScope，树 `[14]`，一个槽，贪心，temperature 0，最多 100 个新 token，seed 123，thinking 关。数据是 SpecBench 每类前 2 条，共 26 条。

## 五、刻意不做

不重跑 777、704、680。不用 next 52 或 last 52 来选 γ。不扫 β 和 λ。不跑 480 条，不加深树。
